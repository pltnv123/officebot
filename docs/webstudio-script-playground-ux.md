# WebStudio Script Playground UX

## Overview

The Script Playground provides a project-based workspace for viewing, editing, and running Python script packages generated by WebStudio.

## Current Implementation (WEBSTUDIO-UX-SCRIPT-PLAYGROUND-002 — V2)

### Visual Structure

**Top Section: Status Bar**
- 🐍 script.py chip (blue)
- 📋 Scenario chip
- 📦 Version chip
- ⚠️ Unsaved changes chip (amber, shown when edited)
- ✅ Saved chip (gray)
- ✅ Test passed chip (green)
- ⚙️ Status chip (right-aligned, shows run state)

**Status Labels:**
- `Ready` — idle, ready to run
- `Starting…` — run initiating
- `Running…` — execution in progress
- `✅ Completed` — successful finish
- `❌ Failed` — execution error
- `⏹️ Stopped` — user stopped
- `⚠️ Stream disconnected` — SSE connection lost

**Action Buttons (Primary Row):**
- ▶️ Run Edited (primary, blue gradient) — runs edited script.py
- ▶️ Run Live (secondary) — runs original artifact
- ⏹️ Stop (secondary, red, disabled when not running)
- 🗑️ Clear (secondary) — clear terminal
- 💾 Save Version (secondary) — create version snapshot
- ⏪ Restore (secondary) — restore from version
- 📥 Download ZIP (secondary) — export artifact
- 🔗 Open Delivery (secondary) — open delivery page

### File Explorer Panel (Left Column) — V2

**Location:** Left side of Script Project Workspace  
**Element ID:** `script-file-list-panel`

**Visual Improvements:**

- Helper text below list: "💡 Only `script.py` is editable in this milestone"

**Displayed Files:**

- `sample_output.txt` — read-only (expected output)
- `actual_output.txt` — read-only (actual run output)

**Behavior:**
- Click any file to open it in the Editor/Preview panel
- Selected file is highlighted with blue left border
- Editable files show "editable" badge (blue chip)
- Read-only files show "read-only" badge (gray chip)
- File list refreshes on new script generation

- Only `script.py` is editable in this milestone
- Edits are stored in session state (not persisted to backend)

**Read-Only Files:**
- Displayed in scrollable pre/code block
- Content loaded via safe_routes from artifact
- No path traversal allowed

### Execution Controls

**Run Live Button** (`run-live-btn`):
- Runs the current generated script
- Opens live terminal with streaming stdout/stderr

**Run Edited Button** (`run-live-edited-btn`):
- Runs the edited script.py content
- Sends edited_source to backend live-run endpoint
- Output appears in live terminal

**Stop Button** (`stop-live-btn`):
- Requests stop of running execution
- May not terminate immediately

### Versioning

**Current Behavior:**
- Versions are created via "Save Version" button (existing flow)
- Version selector dropdown in file panel header
- Restoring version updates editor content
- Selected file context preserved after restore

**Session-Only Save:**
- "Save File" button saves to session state only
- Does not create backend version
- Future milestone: persist edited files

## Safety Rules

### Backend Routes
- All file access via `safe_routes` mapping
- No arbitrary filesystem paths
- No path traversal (`../`)
- Only whitelisted files accessible
- No secrets exposed in routes

### Frontend
- No innerHTML with unsanitized content
- All DOM access via safe helpers (`$`, `$$`, `safeSetText`, `safeClassToggle`)
- Optional chaining (`?.`) for potentially null elements
- No eval/exec of generated code
- Clipboard API only for copy button

### Execution
- No real Telegram tokens in demo
- No arbitrary shell execution
- Bounded demo scenarios only
- Safety level: `bounded_demo`
